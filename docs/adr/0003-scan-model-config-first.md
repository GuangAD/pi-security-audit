# 0003 - 扫描引擎模型:配置优先,会话模型回退

日期:2026-10-19 | 状态:已采纳

## 背景

pi-security-audit 的扫描引擎是 pi subagent(执行审计方法论的模型)。旧插件(pi-codex-security)的 ADR-0001 决定「跟随会话模型」——为了账单透明:用户在哪个模型会话里,就用哪个模型扫描。

实践暴露的问题:会话模型是日常对话用的,频繁切换、协议各异(chat-completions 网关居多);而扫描需要稳定、可预算、协议兼容(Responses 系)的引擎模型。两者耦合导致:换会话模型就换扫描引擎,质量与成本不可预测。

## 决策

扫描引擎模型的解析顺序:**配置优先 → 会话模型回退 → 显式报错**。

1. `<agent-dir>/security-audit.json` 存在且合法 → 使用配置模型(source=config)。
2. 无配置 → 使用当前会话模型(source=session)。
3. 两者皆无 → 显式报错,附补救指引。
4. 损坏配置(非法 JSON/缺 model/缺 provider 前缀)→ 显式报错,**不静默降级**到会话模型——坏配置必须被看见。

## 理由

- 与 ADR-0001 相反的优先级是**有意的设计反转**:扫描引擎与会话对话是两类负载,解耦后各自独立演进。
- 配置一次、永久生效;会话模型随便换,扫描质量不受影响。
- 损坏配置不静默降级,与「密钥不静默」「不静默换模型」同一哲学:让错误被看见,而不是被吞掉。

## 后果

- 用户首次使用需决定是否写配置(不写也能用——回退会话模型,前提是会话模型协议兼容)。
- 协议兼容性检查不再需要(旧 llm-wiring 的映射表随 cs 路线废弃):subagent 直接用 pi 会话/配置的模型,pi 自身负责通信。
