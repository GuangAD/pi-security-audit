# 0001 - 扫描引擎 LLM 跟随会话模型

日期:2026-10-16 | 状态:已被 0003 取代(2026-10-19,cs/codex 路线证伪,见 docs/plans/2026-10-19-security-audit-rewrite/design.md)

## 背景

cs 扫描引擎需要 OpenAI Responses 协议的 LLM 端点,产生真实推理费用。用户环境:pi 配置了多个第三方 LLM 服务(默认智谱 GLM Coding Plan),无 OpenAI 凭证,cs 未登录。扫描费用走谁的账号、用哪个模型,必须显式决策;且用户要求「/model 切换后扫描跟着换」,即模型选择权留在会话层。

## 决策

扫描引擎的 LLM 接线按三级解析:

1. 默认读取 pi 会话当前模型(`pi.getModel()`):Responses 协议直连;Chat 协议查内置端点映射表(首期仅智谱系);模型 id 原样透传 cs。
2. 会话模型不兼容时,读取扫描专用覆盖配置 `~/.pi/agent/codex-security.json`。
3. 覆盖配置也没有 → 显式报错,提示 /model 切换或写配置;**永不静默回退到其他模型**。

凭证一律自动取自 pi 配置(auth.json → models.json → 环境变量降级),经子进程环境变量注入,不进命令行、不落盘。

## 为什么不用 固定单一模型

丢失 /model 的计费与质量选择权;用户明确要求跟随会话(访谈 round 3)。

## 为什么不用 跟随 + 自动回退默认模型

不兼容时静默换模型,用户在不知情时用别人的账号计费,违反计费透明;显式报错把选择权还给用户。

## 为什么不用 要求用户设环境变量

用户明确选择「自动读 pi 配置」(round 2);多一步手工配置违背零配置目标。内部格式依赖风险隔离在 llm-wiring 单模块,读不到自动降级环境变量路径。

## 后果

好处:/model 即扫描模型选择器,零配置,计费透明(用什么模型扫什么档,由会话直接可见)。

代价:依赖 pi 内部文件格式(auth.json/models.json),pi 升级可能破坏读取——降级链与单模块隔离缓解;协议映射表需随 provider 生态维护(新 Chat 协议 provider 需手工加条目);Anthropic 等不兼容协议永远无法用于扫描,只能报错引导切换。
